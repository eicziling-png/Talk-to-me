# Talk to me 设计决策记录

## 当前 UI 风格为何如此

产品被定义为“安静的思想房间”，不是科技产品。视觉方向吸收参考画面的空间关系：冷色/水彩区域承载内在和未知，暖色阅读区域承载理解与交流，门框、地面光影和植物等元素只作为有意义的空间叙事。网页因此采用暖米白、深蓝、棕色、少量绿色和局部暖光，保留纸张/油画质感，避免渐变、玻璃拟态、霓虹、3D 卡片和过度阴影。

## Homepage 设计原则

- Figma `05 Sketch redesign > Talk to me - Homepage` 是主要视觉来源；1440×900 只是参考 Frame，不是网页固定尺寸。
- 首页直接承担“认识人物并开始聊天”的入口，不再要求用户经过专家选择页或专家介绍页。
- 画面保留主体插画、标题 `TALK TO ME`、中文标语、专家姓名入口和低调安全说明。
- 专家入口以两列 4×2 结构呈现：左列为弗洛伊德、克莱因、温尼科特、比昂；右列为拉康、科胡特、欧文·亚隆、`Let's party :)`。
- `Let's party :)` 使用右列圆点和 Calibri；中文专家姓名和其他中文文本遵循现有中文字体规则。
- 宽度不足时使用 grid/flex 与既有 breakpoint 保护文字区，优先保证文字完整可读，不允许覆盖插画。

## Chat page 设计原则

- Chat 继承 Homepage 的插画、米白背景、光影和空间质感；不使用旧版深蓝几何背景或普通聊天软件布局。
- 专家信息、消息记录、输入框均位于同一个空间容器中；消息区独立滚动，composer 固定在底部，不得进入消息滚动区。
- 专家回复和用户消息使用左右分开的 message lane，并保持大量留白、文学化阅读节奏，而非大面积圆角气泡。
- 加载中显示“对方输入中...”，只有真正请求失败/超时/中断时才显示可重试提示。
- Chat 在窄屏下沿用 Homepage 的响应式保护：收缩或下移插画区域，让聊天文字、专家栏和输入区优先完整可见。

## 已否决的方案及原因

- **把理论直接写进回复**：会变成心理学教材，违反“理论隐藏、先听见当前消息”的产品目标。
- **用关键词触发固定心理分析模板**：曾导致“你好”被误判为焦虑/孤独；现改为统一 Conversation Engine 和阶段指导。
- **恢复 Jung**：专家库已经将 Carl Gustav Jung 替换为 Jacques Lacan；不要把荣格的 collective unconscious、archetype、shadow 内容迁回拉康。
- **专家选择页 + 独立专家介绍页**：增加决策层级且重复资料；当前首页直接展示人物入口。
- **ChatGPT/微信/SaaS 式聊天 UI**：与安静的人文空间冲突；改为插画空间中的两条文字交流 lane。
- **多次串行模型调用来做意图分类、审核和回复**：会增加失败率和延迟；当前主要回复路径保持一次主要模型调用，并在同一服务中执行安全/恢复逻辑。
- **固定 px 画布**：在缩放和窄窗口下导致插画、标题、消息重叠；改用 viewport、grid、flex 和 `min-height: 0` 等响应式约束。
- **现在就实现七位专家共同回复**：群聊后端、专家间互动和多角色调度尚未完成；`/chat/party` 目前只保留 UI 外壳和本地输入。
- **群聊顶部显示七位参与者清单**：已删除，避免头部信息块挤压聊天内容；保留“七位历史心理学家的共同房间”标题。

## Figma 相关规则

- 当前实现只以最新确认的 Figma 页面为视觉来源，不用旧截图、旧素材或旧 Hover/Prototype 推断静态页面。
- Homepage 与 Chat 要共享空间比例、插画比例、容器边界和响应式原则，但 Chat 只把 Figma chat UI 叠加到 Homepage 背景上。
- 优先复用 Figma 中的素材、Auto Layout 关系和明确 spacing；避免以 magic number、绝对定位修正普通 UI 错位。
- 未在仓库中完全固化的 Figma 字体授权、变量命名和逐像素测量：需要人工确认。
